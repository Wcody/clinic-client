# 身高体重跟踪管理实现方案

## 1. 背景与目标

当前系统已经在挂号页面采集身高、体重，并且已将挂号当次身高、体重统一记录到 `bq_registration`。下一步需要把这两个字段从普通录入项升级为可持续跟踪的体征管理能力。

目标是形成如下闭环：

```text
挂号录入身高体重
  -> 保存到 bq_registration 当次快照
  -> 同步更新 bq_patient 当前值
  -> 接诊页展示本次/最近体征
  -> 患者详情查看历史趋势
  -> 自动计算 BMI 和变化提醒
```

## 2. 产品定位

身高体重跟踪管理属于轻量体征管理，不是独立慢病模块。

它的价值是：

- 帮助医生快速了解患者当前体格状态。
- 保留每次挂号时的身高、体重快照。
- 支持长期趋势查看，尤其是体重管理、儿童生长、慢病随访。
- 为后续 BMI、儿童生长曲线、按体重用药提醒打基础。

## 3. 数据设计

第一期不新增独立体征表，使用现有患者表和挂号表。

| 表 | 字段 | 含义 |
|---|---|---|
| `bq_patient` | `height` | 患者当前/latest 身高，单位 cm |
| `bq_patient` | `weight` | 患者当前/latest 体重，单位 kg |
| `bq_registration` | `height` | 本次挂号时身高快照，单位 cm |
| `bq_registration` | `weight` | 本次挂号时体重快照，单位 kg |
| `bq_registration` | `firstAge/lastAge/ageType/age` | 本次挂号时年龄快照 |

设计原则：

- 患者表保存当前值。
- 挂号表保存当次快照。
- 趋势从挂号历史生成。
- 病历表暂不作为主链路使用，病历可通过 `regId` 关联挂号快照。

## 4. 后端接口方案

建议新增轻量接口，放在 `registration` 下，因为历史数据来自挂号表。

### 4.1 获取最近体征

```http
GET /registration/body-metrics/latest/{patientId}
```

返回字段：

```json
{
  "regId": 123,
  "orderTime": "2026-05-21 10:20:00",
  "height": 170,
  "weight": 68.5,
  "bmi": 23.7,
  "bmiLevel": "正常",
  "weightChange": 1.2
}
```

### 4.2 获取体征历史

```http
GET /registration/body-metrics/history/{patientId}
```

可选参数：

- `limit`
- `startTime`
- `endTime`

返回列表字段：

| 字段 | 说明 |
|---|---|
| `regId` | 挂号 ID |
| `orderTime` | 挂号时间 |
| `department` | 科室 |
| `doctor` | 医生 |
| `age` | 当次年龄 |
| `height` | 当次身高 |
| `weight` | 当次体重 |
| `bmi` | BMI |
| `weightChange` | 较上次体重变化 |

### 4.3 获取体征摘要

```http
GET /registration/body-metrics/summary/{patientId}
```

返回：

- 最新身高
- 最新体重
- 最新 BMI
- 最近一次体重变化
- 近 3 次体重变化
- 记录次数
- 首次记录日期
- 最近记录日期

## 5. BMI 计算与提示规则

BMI 计算：

```text
BMI = 体重kg / (身高m * 身高m)
```

保留 1 位小数。

成人 BMI 提示第一期可采用：

| BMI | 提示 |
|---|---|
| `< 18.5` | 偏瘦 |
| `18.5 - 23.9` | 正常 |
| `24.0 - 27.9` | 超重 |
| `>= 28.0` | 肥胖 |

儿童患者第一期不直接套成人 BMI 结论，只提示：

```text
儿童体重状态建议结合年龄、性别和生长曲线综合判断。
```

## 6. 异常提醒规则

第一期只做温和提醒，不做诊断。

| 场景 | 提醒 |
|---|---|
| 本次身高低于上次 | 请确认身高录入是否准确 |
| 本次体重较上次变化超过 5kg | 请确认体重录入是否准确 |
| BMI 超重或肥胖 | 建议关注体重管理 |
| 儿童患者 | 建议结合儿童生长曲线判断 |
| 长期缺少体重记录 | 建议补录体重，便于趋势跟踪 |

提醒只提供参考，最终判断由医生完成。

## 7. 前端功能方案

### 7.1 挂号页面

在身高体重输入旁增加即时反馈：

```text
BMI 23.7 正常
较上次体重 +1.2 kg
```

交互：

- 输入身高、体重后自动计算 BMI。
- 选择已有患者后展示上次记录。
- 变化过大时显示黄色提醒。
- 保存挂号时写入 `bq_registration.height/weight`。
- 同步更新 `bq_patient.height/weight`。

### 7.2 挂号详情页

右侧挂号信息展示当次快照：

```text
身高：170 cm
体重：68.5 kg
BMI：23.7
```

左侧患者信息仍展示和维护患者当前档案值。

### 7.3 医生接诊页

患者顶部信息区增加体征摘要：

```text
身高 170 cm | 体重 68.5 kg | BMI 23.7 | 较上次 +1.2 kg
```

点击可展开最近 3 次记录：

```text
2026-05-21  68.5kg
2026-04-20  67.3kg
2026-03-18  67.0kg
```

### 7.4 患者详情/就诊记录页

新增“体征趋势”区域：

- 最新记录卡片
- 体重趋势图
- BMI 趋势图
- 身高趋势图
- 历史记录表

历史表字段：

```text
日期 | 年龄 | 身高 | 体重 | BMI | 较上次 | 科室 | 医生 | 挂号号
```

## 8. 后端实现步骤

1. 确认 `BqRegistrationEntity` 包含 `height/weight`。
2. 确认 `bq_registration` 数据库表包含 `height/weight`。
3. `BqRegistrationMapper.xml` 查询列表补充 `height/weight`。
4. 新增 `BodyMetricsVo`。
5. 新增 Mapper 查询：
   - 按 `patientId` 查询有身高体重的挂号记录。
   - 按 `orderTime` 倒序。
6. Service 层计算：
   - BMI。
   - BMI 等级。
   - 与上次体重差。
   - 异常提醒。
7. Controller 暴露接口：
   - `latest`
   - `history`
   - `summary`

## 9. 前端实现步骤

1. `register.ts` 补全挂号体征类型。
2. 挂号页增加 BMI 计算展示。
3. 挂号页选择患者后拉取最近体征。
4. 挂号保存时写入挂号快照。
5. 挂号详情页显示快照体征。
6. 医生接诊页顶部展示体征摘要。
7. 新增体征趋势组件：
   - `BodyMetricsSummary.vue`
   - `BodyMetricsTrend.vue`
   - `BodyMetricsHistoryTable.vue`

## 10. 优先级规划

### P0

- 挂号保存身高、体重快照。
- 挂号详情显示身高、体重。
- BMI 自动计算。
- 接诊页显示最近体征。
- 历史表格。

### P1

- 体重折线图。
- BMI 折线图。
- 身高折线图。
- 较上次变化。
- 异常录入提醒。

### P2

- 儿童生长曲线。
- 按年龄、性别展示参考范围。
- 慢病体重管理目标。
- 复查提醒。

### P3

- 体重管理报告。
- 患者端健康建议。
- 儿童用药体重剂量提醒。
- 结合诊断生成随访建议。

## 11. 验收标准

1. 新增挂号填写身高体重后，`bq_registration` 有当次快照。
2. 患者表 `bq_patient` 同步为最新身高体重。
3. 挂号详情能看到当次身高体重。
4. 医生接诊页能看到最近体征。
5. 历史趋势只使用该患者自己的挂号记录。
6. BMI 计算正确。
7. 修改患者当前身高体重不会影响历史挂号快照。
8. 就诊记录列表中的年龄、身高、体重均以挂号快照为准。

## 12. 后续注意事项

- 儿童 BMI 不应直接套成人分类。
- 体重变化提醒不要作为诊断结论。
- 趋势图要允许缺失值，不强制每次挂号都有身高体重。
- 如果未来需要和病历打印强绑定，可以通过 `regId` 从挂号表读取体征快照。
- 如后续体征扩展到血压、体温、血糖，建议再引入独立体征记录表。
